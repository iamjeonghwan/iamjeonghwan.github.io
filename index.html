00Bio

I started my career on the fab floor, not in a notebook. Years spent running wafer test protocols and troubleshooting components on Advantest, Teradyne, and Accretech platforms taught me to read a sensor reading the way an engineer reads a datasheet — as a signal with a physical cause, not just a number in a column. That instinct is what pulled me toward data science: I wanted the statistical and machine-learning training to test those signals as rigorously as I once diagnosed hardware.

At Syracuse University, I've built that rigor around the same instincts — treating a defect map from a wafer line and a customer-ratings table from an OLTP system as the same kind of problem: extract the signal, respect the physics or process context behind it, and stay honest about what a model can and can't claim. I'm now looking for a Data Scientist / Data Engineer role where that combination of hardware fluency and data-science discipline is an asset, ideally in a semiconductor or industrial data setting.

02IST 707
Semiconductor Wafer Defect Prediction — EF-PIPELINE v3.1
Autoencoder Feature Extraction · Ensemble Trees · SHAP

Semiconductor fabrication generates highly collinear sensor readings where subtle tool deviations cause compound yield drops. Rule-based single-variable alerts miss non-linear multivariate interactions, so I built a leakage-safe pipeline that compresses the inline parameter grid and learns those interactions directly.

DataSECOM dataset (UCI ML Repository): 1,567 wafers across 591 continuous inline tool parameters with heavy class imbalance.
ApproachPython, Scikit-Learn, CatBoost, XGBoost, Neural Network Autoencoders (MLPRegressor), RobustScaler, SHAP.
ResultsPrevented data leakage by fitting preparation statistics inside train folds only; removed >15% missing and constant parameters and applied a Pearson correlation filter (|r| > 0.8). Autoencoders compressed the high-dimensional grid into a latent space, and an optimized Random Forest reached a 0.98 Test AUC (0.94 accuracy, 0.91 recall) under cross-validation. SHAP identified Viscosity, Reaction Temperature, and Mixing Time as leading failure drivers.
NextGained experience handling sparse classes and safe scaling. Next: embed the pipeline into a stream-based early-warning engine.

03IST 691
PCB Defect Detection & Segmentation
YOLOv8 · U-Net · TensorFlow / Keras · OpenCV

Manual inspection of printed circuit boards is slow and inconsistent. I chained two models instead of asking one to do both jobs: a YOLOv8 detector locates each defect, then a U-Net delineates it at pixel level — detection for triage, segmentation for measurement.

DataPCB defect imagery evaluated on 139 test images carrying 601 labeled instances across six defect classes.
ApproachStage 1: YOLOv8 bounding-box detection. Stage 2: regions of interest cropped from the detector output and passed to a Dice-loss-trained U-Net for pixel-level masks. TensorFlow / Keras and OpenCV.
ResultsDetection reached 0.971 mAP@50 with precision and recall both at 0.966. Segmentation reached 0.939 mean Dice, 0.892 mean IoU, and a 0.939 best-threshold F1.
LimitThe segmentation masks were heuristically auto-generated from YOLO crops rather than hand-annotated. The Dice score therefore validates pipeline mechanics, not ground truth — stated here rather than buried in an appendix.
NextReplace the auto-masks with manual ground-truth annotation to test the assumption the Dice score rests on.

04IST 664
Support Ticket Categorization & Dataset Quality Diagnosis
NLTK · Bag-of-Words · 10-Fold CV · Zipf's Law Diagnostics

Support teams manually read, tag, and route thousands of tickets daily, causing delay. This project builds an automated text-classification engine using classical NLP features plus request metadata — and, when accuracy refused to move, diagnoses why instead of tuning blindly.

DataKaggle Enterprise Support Ticket Corpus: 8,469 transcripts across 5 categories (Billing, Cancellation, Product, Refund, Technical).
ApproachPython, Pandas, NLTK (tokenization, stopwords, FreqDist, Naïve Bayes), Scikit-Learn, Zipf's Law diagnostics.
ResultsBuilt regex extractors to drop template placeholders, numeric strings, and email blocks. Compared a 1,000-unigram boolean Bag-of-Words baseline against an augmented feature set (priority tags, channel, length flags). Under 10-fold cross-validation, adding metadata shifted macro F1 from 0.1960 to 0.2002. Rather than a modeling flaw, Zipf's Law and distribution diagnostics proved the dataset suffered from heavy label noise and template overlaps — and the project used these insights to propose essential data governance steps prior to production deployment.
NextPracticed token-level extraction and diagnostic evaluation. Next: migrate to transformer embeddings (BERT) and real-world logging data.

05IST 659
Starship Relaunch — Relational Database Design
SQL Server · T-SQL · Stored Procedures · Triggers

A playable text adventure driven entirely at the data layer. Movement, lock logic, and win conditions are enforced by T-SQL stored procedures and triggers rather than application code — the database is the game engine, not just its storage.

DataA normalized 8-table schema carrying 19 constraints across rooms, items, players, inventory, and state transitions.
ApproachSQL Server with T-SQL stored procedures and triggers holding the game rules, declarative referential integrity guarding state, and a Docker Compose setup with a thin Python driver so the whole game stands up from scratch reproducibly.
ResultsRoom-to-room movement, lock-and-key logic, and win conditions all resolve inside the database. The 19 declarative constraints make invalid game states unrepresentable rather than merely unhandled — no application-side guard clause can be forgotten.
TakeawayPushing invariants down into the schema is cheaper than defending them in every caller above it.

06IST 686
School Vaccination Exemption Modeling
R · OLS · Logistic Regression · Null-Result Reporting

Do school type and enrollment size predict vaccination exemption rates? I fitted both a linear and a logistic model, and no coefficient reached significance. The interesting part of this project is what I did with that.

ApproachR (lm and glm): OLS regression on exemption rate and logistic regression on exemption incidence, with school type and enrollment as predictors.
ResultsThe OLS model explained effectively none of the variance (R² = 0.006). The logistic model returned an odds ratio of 0.93 at p = 0.753 — statistically indistinguishable from no effect at all.
TakeawayReported as a clean null result rather than an overstated weak effect. Framing a 0.753 p-value as a “trend” would have been the easier write-up and the less defensible one.

07IST 652
AI Investment Boom vs. Big Tech Layoffs, 2020–2024
Multi-Source Scripting · yfinance · Web Scraping · VADER

Did the AI investment boom and the big-tech layoff wave actually move together? I combined four sources spanning structured, semi-structured, and unstructured data to test the question — then was deliberate about what the answer could and could not support.

DataFour sources across three data types: layoff records, yfinance market prices, BBC headlines scraped via the Wayback Machine, and 647 Reddit posts.
ApproachPython multi-source ingestion and reconciliation, share-of-coverage analysis on the headline corpus, VADER sentiment scoring on the Reddit text, and correlation analysis across the 2020–2024 window.
ResultsAI's share of scraped headlines rose from 1.8% to 8.3% over the window, concurrent with the layoff wave — but the correlation between the two series was only +0.11.
TakeawayConcurrency is not causation. With a correlation that weak, the deliverable states the relationship as co-occurrence and stops there.
